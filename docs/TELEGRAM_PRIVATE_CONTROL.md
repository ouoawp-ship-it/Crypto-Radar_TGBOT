# Telegram 管理员私聊菜单（第一版）

第一版把最常用的日常查看和两个低风险开关放进 Bot 私聊。它是一个独立、
默认关闭的服务，不加入主 BOT 或市场数据进程；故障不会停止五个雷达。

## 私聊里可以做什么

- 查看五个雷达是否正常；
- 查看本地健康摘要；
- 查看最近一小时真实推送额度；
- 查看五个雷达话题是否已配置；
- 二次确认后开启或关闭多周期方向雷达；
- 二次确认后开启或关闭 AI 白话解读。

只接受 FinalShell 预先绑定的管理员本人私聊。群消息、其他用户、机器人消息、
转发消息和任意自定义命令全部忽略。Telegram 中不显示 Token、群号、话题号、
API Key、接口地址、文件路径或原始错误正文。

## FinalShell 继续保留什么

以下操作不进入第一版私聊菜单：

- 绑定或解除管理员；
- 设置 Telegram Token、群号、AI Key、AI 地址和模型；
- 切换主 BOT 真实发送、发送真实测试消息、修改真实发送确认；
- 创建、修复、删除话题或重新置顶；
- 安装、更新、部署、版本切换和回滚；
- 启停主 BOT、市场数据服务及修改 systemd；
- 数据库备份、恢复和清理；
- 查看完整日志、进程参数、原始 JSON 和内部路径。

一句话边界：Telegram 私聊负责“日常查看 + 两个安全开关”，FinalShell 负责
“身份、密钥、真实发送、服务、部署、日志和恢复”。

## 首次启用

在服务器运行 `paopao`，进入：

```text
Telegram 设置与测试
→ 管理员私聊菜单（第一版）
```

先设置管理员 Telegram User ID，再选择“开启并启动私聊菜单”。所有输入按现有
部署要求在 FinalShell 明文显示；保存后的状态仍只显示已配置或未配置。
更换管理员时会先停止服务并取消开机自启，写入成功后才按原状态恢复，因此旧管理员
不会在配置切换期间继续有效；写入失败则保持停止且不会在服务器重启后自动运行。

配置默认值：

```dotenv
TG_PRIVATE_CONTROL_ENABLE=false
TG_PRIVATE_CONTROL_ADMIN_USER_ID=
```

服务名为 `paopao-private-control.service`。安装和更新只安装它的安全启动配置，
默认不会启动或设为开机自启；必须由操作者显式开启。

## 生效与安全说明

方向雷达和 AI 开关均需要二次确认。方向雷达基础功能未准备好时拒绝开启；
AI 配置不完整或方向雷达未开启时拒绝开启 AI。配置仍通过现有管理器执行文件
锁、修改前备份、原子写入、写后校验和失败恢复。主 BOT 会在下一轮雷达任务
重新读取这两个开关，不需要从私聊执行服务器重启。

私聊菜单没有真实发送模式入口，不会修改主 BOT 的双重真实发送门禁，也不会
向生产群或五个雷达话题发送管理消息。
